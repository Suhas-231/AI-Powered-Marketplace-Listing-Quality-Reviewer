## 4. Important AI-Generated Code

Key components generated by the AI assistant:
1. **`backend/app/services/groq_service.py`**:
   - `GroqService.analyze_listing`: Uses `groq.Groq`, Chat Completions API with structured outputs (`response_format={"type": "json_schema"}`), fallback to JSON mode (`response_format={"type": "json_object"}`), error retries with exponential backoff, and markdown code fence cleaning (`_clean_and_parse_json`).
2. **`backend/app/services/policy_service.py`**:
   - `PolicyService.retrieve_relevant_policies`: Ranks policies by category match and keyword heuristics.
   - `PolicyService.verify_policy_citations`: Cross-checks AI-returned policy codes against actual database records to flag hallucinated citations.
3. **`backend/app/services/validation_service.py`**:
   - `ValidationService.normalize_title`: Punctuation stripping, lowercasing, and whitespace normalization.
   - `ValidationService.check_duplicate`: Compares normalized titles and Jaccard token overlap against existing database records.
4. **`backend/app/routes/suggestions.py`**:
   - Implements atomic human approval, editing, and rejection transactions that safely update listing fields and persist `ReviewAction` and `AuditLog` records.
5. **`frontend/src/pages/ReviewReport.jsx`**:
   - Visual side-by-side comparison of original content vs suggested revision vs final edited text, complete with field-by-field approval and progress tracking.

## 5. AI Mistakes Encountered and Manual Corrections

During the build process, several automated code generation issues were identified and corrected:

1. **SQLAlchemy Re-initialization Crash (`RuntimeError`)**:
   - *Problem*: In `backend/app/database.py`, an initial implementation attempted to call `db.init_app(app)` a second time when falling back from MySQL to SQLite. Flask-SQLAlchemy 3.x threw `RuntimeError: A 'SQLAlchemy' instance has already been registered on this Flask app`.
   - *Correction*: Refactored `database.py` with `verify_and_configure_database(app)` to test the MySQL connection using `pymysql.connect()` directly *before* calling `db.init_app(app)`, switching to SQLite cleanly beforehand if MySQL credentials were not yet configured.

2. **Dialect-Specific JSON Query (`AttributeError: Neither 'BinaryExpression' object nor 'Comparator' object has an attribute 'astext'`)**:
   - *Problem*: In `backend/app/routes/history.py`, the AI generated PostgreSQL-specific syntax `AuditLog.details['listing_id'].astext == str(listing.id)`. In SQLite and MySQL, `astext` does not exist on JSON comparators.
   - *Correction*: Replaced the query with dialect-neutral relational filters using `entity_type='listing', entity_id=listing.id` and associated suggestion IDs for action logs.

3. **CSV Parsing NoneType Exception**:
   - *Problem*: In `backend/app/routes/batch.py`, `import_csv` attempted `row.get('tags', '').split(',')`. When a CSV row had fewer columns than headers, `row.get('tags')` returned `None`, raising `'NoneType' object has no attribute 'split'`.
   - *Correction*: Replaced with `raw_tags = row.get('tags') or ''` and conditional list comprehension `[t.strip() for t in raw_tags.split(',') if t.strip()] if raw_tags else []`.

4. **Pytest Path Resolution (`ModuleNotFoundError: No module named 'app'`)**:
   - *Problem*: Calling `pytest` directly in PowerShell did not add `backend/` to `sys.path`.
   - *Correction*: Standardized execution to `python -m pytest -v`, which correctly sets Python module resolution.
